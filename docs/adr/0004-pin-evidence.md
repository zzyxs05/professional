# ADR-0004 · 钉证据机制：LLM 提疑、规则钉证据

- 状态：已采纳（2026-10-14）
- 决策人：周宗正
- 关联：总档 §3.5、`core/fusion.py`、`specification.md`

## 背景

B 通道（LLM）能提出语义疑点，但它的输出不可直接采信；而融合层又必须给出确定性结论。
需要一个"把语义疑点重新锚回机械事实"的机制。

## 决策

**钉证据（pin_evidence）**：把 B 侧疑点翻译为可机械验证的事实断言，逐类核对：

| 疑点类型 | 钉法 |
|----------|------|
| 组件/权限/属性类 | 核对 manifest 事实（自研直读，含行号坐标） |
| 字符串/端点/凭据类 | dex/res 原文检索回放（classesN.dex#str[索引] 定位） |
| 类/方法结构类 | smali 类文件存在性核对 |

**钉成功 → 升「已确认」（附机械证据）；钉失败 → 保留「待复核」并标注未钉原因。**
已由 A 通道覆盖的规则不再重复出结论。

## 理由

- 保证"升级到已确认"的路径只有一条：机械事实——LLM 无权直接升级任何结论；
- 钉证据的产出（locations + facts）落盘为 `pin_evidence` 类型证据，可被第三方按坐标复核；
- 该机制同时是 A 的补盲通道：B2 提疑 + 钉成功 = A 漏报的确定性补齐。

## 后果

- `fusion.build_conclusions` 接收 `pin_fn` 注入（流程层绑定 ctx 与证据库）；
- 测试层验证：模糊疑点（"可能存在后门"）必然钉失败，不得凭空给出可核查坐标；
- 限制：钉证据依赖 claim 中出现可核查对象（组件名/URL/类名），纯抽象描述会被拒绝——
  这是刻意保守：宁可留「待复核」，不造假证据。

## 替代方案（被否）

- LLM 直接升级结论：不可审计，违证据纪律；
- 不钉、B 疑点一律丢弃：丢失 A 漏报的补齐机会。
