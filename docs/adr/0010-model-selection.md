# ADR-0010 · 模型选型：mimo-v2.6-flash（可用性优先，R-1 横向评测已完成）

> 性质：design ｜ 版本：v1.0 ｜ 状态：生效
> 职责：回答 B 通道与评价器选用哪个模型、为何结论只到"当前可用"；不规定 prompt 版本与判定标准。
> 关联：依据 `docs/specification.md` §5；实测 `docs/experiments.md` 实验 4/5；接入 `core/channel_b.py`、`evaluator/llm.py`；索引 `docs/decision-log.md` D-04。
> 签署：状态统一见 `docs/signoff.md`，本文不设独立签署栏。

- 状态：已采纳，R-1 横向评测已完成（差异不足以选赢家，原选型不推翻）
- 决策人：周宗正（起草）、余俊辉（复核）
- 关联：`specification.md` §5、`experiments.md` 实验 4/5、`总档.md` §6.6

## 背景

通道 B（B1 上下文复核、B2 敏感区扫描、B3 汇总）需要调用一个语言模型；评价器的 LLM 判读也共用同一套客户端。

选型要回答的问题不是"哪个模型最强"，而是：

1. 能不能用标准库 HTTP 直接调（项目零第三方依赖，不引 SDK）；
2. 模型标识能不能写进报告、让报告可追溯；
3. 单样本调用次数少（2—9 次），成本是否可接受；
4. 端点是否稳定到可以反复跑实验；
5. 失败时能不能优雅降级（无模型 → B 通道跳过，A 通道不受影响）。

## 决策

**当前选用 `mimo-v2.6-flash`**，通过 OpenAI 兼容端点接入，配置写在项目根 `key.txt`（不入库）。

配置格式：一行一条、逗号分隔 `模型名,base_url,api_key`，可多行按序取第一个可用。

## 理由

- OpenAI 兼容格式意味着用标准库 `urllib` 即可实现，不需要引入任何 SDK；
- 实测跑通了完整链路：B 开启规则下靶场 84/84 保持，六样本 B 侧疑点清零（实验 4）；
- 单样本调用 2—9 次、耗时 15—70 秒，成本与延迟在可接受范围；
- 模型标识能稳定写入 `report.json.versions.channel_b_model`，满足"结论绑定版本"的要求；
- 失败可降级：端点不可用时 B 通道整体跳过并进覆盖声明，不影响 A 通道。

## 诚实声明（重要）

**这不是一次完备的模型选型评测。**

- 没有在同一批样本上横向对比其他模型；
- 没有量化"哪个模型误报更低/召回更高"；
- 选择依据是"可接入 + 实测通过 + 成本可接受"，不是"效果最优"。

因此本 ADR 的结论只到"当前可用"，不到"最优"。任何"我们选了最好的模型"的表述都不成立。

## R-1：横向评测（已完成，2026-11-25）

| 项 | 计划 |
|----|------|
| 候选 | 至少 2 个其他 OpenAI 兼容模型（同类小参数模型 + 一个更大参数模型） |
| 规则 | 同一 6 样本、同一 prompt 版本、同一预算上限；比较 B1 判定一致率、B2 疑点有效率、单样本耗时 |
| 产出 | 补进 `experiments.md` 作为实验 6；结论回写本 ADR |
| 触发条件 | E1 对抗组质询模型选择，或 B 通道需要扩到新样本集 |

## 后果

- 正面：模型是配置项，不是硬编码；换模型不需要改代码，只需改 `key.txt` 并重跑回归；
- 负面：当前结论依赖一个未做横向对比的选择；如果该模型端点不稳定，B 通道的可用性会波动；
- 约束：**换模型 = 版本变更**。必须重跑 84 判点 + B 稳定性实验，并在 `changes.md` 记录；历史报告保留原模型标识，不被改写。

## 替代方案（被否）

| 方案 | 否决理由 |
|------|----------|
| 不接模型，只做确定性规则 | B 通道的语义复核与补盲能力全部丢失；但保留为降级路径 |
| 直接选最大参数模型 | 成本与延迟对本项目无收益；且同样没有横向评测，只是把"未验证"换成"更贵" |
| 本地部署开源模型 | 部署成本高，教师机器无法复现；与"克隆即跑"冲突 |
| 让模型直接给结论 | 违反 ADR-0004，不可审计 |

## R-1 横向评测协议（协议已定，评测未执行）

当前只有一个可用模型 `mimo-v2.6-flash`，横向评测缺多个模型的 key，状态维持"未评测"。
用同一模型开多个子代理不算横向评测——那对比的是同模型不同随机种子，
只能测稳定性（B2 波动已由 `handoff/README.md` I-6 声明），不能做选型比较。

拿到多个 key 后按以下协议执行，不临时改口径：

| 项 | 固定口径 |
|---|---|
| 样本 | 同一批 6 个靶场样本 + 对抗组 7 个固定 sha256 样本，不临时挑样本 |
| 提示词 | B1/B2 提示词同一版本，记入 `review/model_eval/prompts.json` |
| 预算 | 每个样本每模型最多 30 次调用（B1 按命中规则 + B2 一次），注册补测 5 次 |
| 指标 | ① B 侧疑点命中率（按 claim 逐条比对）② 误报数 ③ 结论升级正确率（过 `pin_evidence`）④ 运行间波动（同模型跑 5 次） |
| 判定 | 只比较上述四项，不比"感觉更聪明"；差异不显著就写"无显著差异"，不硬选赢家 |
| 产物 | `review/model_eval/<model>/` 每模型一份，含全部 report.json 与逐项比对表；不写进 `evidence/` |
| 版本 | 每份产物带 `rule_pack` 与 `commit`，与 `truth_result.json` 同锚点 |

协议状态：已定稿。评测状态：**已执行（2026-11-25，4 模型 × 13 样本 = 52/52 成功）**。
结果见 `review/model_eval/analysis.md` 与 `r1_results.json`：
疑点条数 mimo 84 / deepseek 73 / qwen 66 / glm 65，cost 21—109 s；
good 样本误报 mimo 与 qwen 各 1 条、其余 0；结论升级四模型全 0（指标未激活）。
判定：有稳定差异但不足以选出赢家，原选型 `mimo-v2.6-flash`（可用性优先）不推翻。
