# ADR-0012 · 评价器通用化：内核与目标解耦，纯 harness 分项评测分与判定分离

> 性质：design ｜ 版本：v1.0 ｜ 状态：草案（待复核）
> 职责：回答评价器如何适配对抗组异题项目、分项评测分如何与机械判定共存；不改审计规则包。
> 关联：上游 ADR-0011、`总档.md` §2.6；实现 `evaluator/checker.py`、`evaluator/html_report.py`、`evaluator/skills/evidence-review/SKILL.md`；变更 `docs/changes.md` S23—S29。
> 签署：状态统一见 `docs/signoff.md`，本文不设独立签署栏。

- 状态：草案（技术实施已完成，待复核）

## 背景

ADR-0011 确定了「Python 受限多轮 Agent，不引入 DeepSeek Harness」，但该实现仍有两处与目标项目耦合：

1. `precheck.py` 直接读 `report.json` 的 conclusions / coverage、检查 APK 规则包与 `ALL_RULE_IDS`；
2. `fieldcheck.py` 与 `fields.json` 把 `evidence/RUN-*/` 写进路径模板，并假设目标有 run_id。

对抗组做的是异题项目，不保证有 run_id、evidence 目录或 report.json。若沿用上述假设，互评只能靠特殊化适配，违背「评价器独立于项目」的要求。此外，原契约规定「模型不产生分数」，但机械层无法判断证据与评分项的关联度——只给四状态会把评价降为文件存在性检查。课程评分框架见 rubric 的 S1—S4（100 分），课程 PPT 章节03 P2 要求评测分必须逐子项给、带理由与证据，不能只报一个总分。

## 决策

1. **内核与目标解耦**：新增 `checker.py`，不 import core、不认任何项目结构；只实现 5 种通用比对方式（`text_all` / `json_eq` / `json_nonempty` / `dir_min` / `file_exists`）。
2. **适配靠数据，不靠改代码**：目标项目提供自己的字段规范，声明看哪些文件/字段；路径模板 `{{name}}` 的变量由 `--context` 注入，缺失即判 missing 并记下变量名，不套默认值、不猜结构。兼容存量 `RUN-*` 写法。
3. **权限边界仍在程序层**：内核的路径白名单由字段规范推导，规范未声明的路径一律拒绝；不提供任意 Shell / URL，符合总档 §2.6「权限防护不是提示词禁令」。
4. **分项评测分与判定分离**：四状态与证据链由机械层收口；模型按课程评分框架 S1—S4 逐子项给评测分（`subcriterion_id` + `score` + `max` + `rationale` + `evidence_ids` + `evidence_level`）。E 项是证据审查项不给分，`score_suggestion` 保持 null；评测分独立在顶层 `evaluation_scores`，不是课程最终成绩。
5. **判定指纹**：`verdict_digest` 只含状态与字段三态，不含模型文本、分数、时间、eval_id；同快照重跑判定区逐字节一致。
6. **两种运行方式**：本地 `cli.py evaluate`；外部 harness 加载 `SKILL.md` 后调 `python -m evaluator.checker`，两者共用同一内核。

## 理由

- **异题适配**：对抗组项目结构未知，任何写死的路径或 run_id 假设都会在互评时失效；靠字段规范适配才能通用。
- **评分现实**：机械层能核字段，不能判断关联度；禁止模型给分等于放弃语义判断。按课程框架逐子项给评测分、每项带理由与证据，既不越权又满足章节03 P2「不等于某个总分」的要求。
- **稳定性**：模型有随机性，所以判定区必须完全脱离模型输出；`verdict_digest` 给出可复核的一致性证据，而不是口头承诺「稳定」。
- **零依赖**：纯标准库实现，外部 harness 只要有 Python 就能调用，不引入 Node 或第三方包，不碰 ADR-0011 的零依赖约束。

## 后果

- 正面：评价器可评任意有字段规范的项目；判定可复算；HTML 每项有人话描述、扣分原因、完整证据链；分项评测分不污染判定。
- 负面：目标项目必须自己写字段规范，否则只能做语义层审查并标「未做字段核对」；这是课程「学生适配」层的责任，由目标项目自己写。
- 契约变更：E 项 `score_suggestion` 保持 null，新增顶层 `evaluation_scores` 按 S1—S4 子项给分；rubric 1.3，需教师确认后冻结；未确认前评价结果为内部草案。

## 被否方案

- **让 checker 认识每个项目的结构**：等于为对抗组特殊化，不可维护；否。
- **保留 run_id 为必填**：无法覆盖无快照概念的项目；否。
- **模型直接给最终成绩**：违反课程「评价器不产出最终成绩」与 ADR-0011；否。
- **把判定也交给模型**：随机性导致同快照分歧，无法复核；否。

## 验证

- 异题合成项目（无 run_id / 无 evidence / 无 report.json）评价 PASS；变量缺失如实判 missing（测试 2 例）。
- 判定区同快照重跑逐字节一致，`verdict_digest` 相同。
- 单测 93/93；K-1~K-6 6/6；靶场 84 判点一致 84、硬错 0。
- 全模型批分项评测分未实跑验证（本轮为 `--no-llm` 确定性路径），如实列为未完成；HTML 渲染已用合成分数验证。


## 追加决策（2026-11-25）：默认不调用 API

API Agent 自主取证受预算限制（10 次交互只读到 6 个文件），15 个评分子项中 5 项因
「未读到证据」标未评。改为默认纯 harness：

- `evaluator/scoring.py` 按 `scoring-fields.json` 的字段三态机械算分，覆盖全部 15 个子项；
- 分数 = match 字段占比 × 满分，扣分理由直接列未满足字段与实际值；
- 这是证据支撑分（证据齐不齐），不是质量主观评价；S4 只核对记录存在，标 CLAIM_ONLY；
- `--llm` 保留为可选，默认不需要 key.txt，新对话一句命令即可跑出完整报告。

被否：继续用 API Agent 自主取证——预算内覆盖不全，且模型输出解析不稳定。
