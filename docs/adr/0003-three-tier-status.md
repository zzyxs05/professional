# ADR-0003 · 结论三档与证据强度上限（静态不到"已确认"的场景显式封顶）

- 状态：已采纳（2026-10-14）
- 决策人：周宗正、余俊辉
- 关联：总档 §3.5、`specification.md` §2/§6

## 背景

"静态疑点"与"已确认问题"混淆是审计报告最常见的不诚实。两类典型：
- R-PERM-01（调度×敏感 API 组合）：静态只能给"嫌疑组合"，给不了真实执行时间；
- R-PERM-03（过度声明）：是排除性结论（"未发现使用"），可能被反射/JNI 规避。

## 决策

三档结论（已确认 / 待复核 / 无法判定）+ **逐规则声明档位上限**：

- R-PERM-01、R-PERM-03 → 上限「待复核」（措辞禁止升级，如不得写"该应用在半夜录音"）；
- R-CODE-01 的 dex 弱模式 → 上限「待复核」；
- 其余直证类规则 → 上限「已确认」；
- **融合层不得越过规则上限**；B 通道整体天花板 =「待复核」。

## 理由

- 真值表本身按此口径标定（bad01 R-PERM-03=REVIEW、bad03 R-PERM-01=REVIEW）；
- "不把合理的不确定性判成错"——`EXPECTED_SILENT` 上出现「待复核」记为噪声（单独统计）而非硬错 FP，
  硬错只追究「已确认」级误报（口径见 `acceptance-matrix.md`）；
- 真值一致性 84/84 的达成正是建立在这个"该软则软、该硬则硬"的档位对齐上。

## 后果

- 报告三档分组渲染；每条结论带 `missing_evidence`（缺口）与定位坐标；
- 档位是"输出契约"的一部分：评价器预检校验状态合法性，抗组可按档位口径挑战。

## 替代方案（被否）

- 统一"已确认"：失去不确定性表达，违反证据纪律第 2/3 条；
- 全部"待复核"：装死式输出，good/bad 样本拉不开区分度。
