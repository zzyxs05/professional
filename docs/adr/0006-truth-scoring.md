# ADR-0006 · 真值一致性评分口径（FP 与噪声的二分）

- 状态：已采纳（2026-10-14）
- 决策人：周宗正、余俊辉
- 关联：总档 §5.3、`docs/acceptance-matrix.md`、`scripts/truth_check.py`

## 背景

真值表三态（应命中 / 应安静 / 不适用）在"应安静"一点上存在判罚歧义：
某规则在干净样本上输出「待复核」，算误报（FP）还是可接受的不确定性表达？

## 决策

判罚口径（写进契约，脚本强制执行）：

| 真值 | 判 PASS | 硬错 | 噪声 |
|------|---------|------|------|
| EXPECTED_HIT:CONFIRMED | 已确认 | 无结论（漏检）/ 档位不足 | — |
| EXPECTED_HIT:REVIEW | 已确认或待复核 | 无结论 | — |
| EXPECTED_SILENT | 无结论 | **已确认**（FP） | **待复核**（单独统计） |

- 硬错 = FP + 漏检 + 档位错（目标 0，验收 A-02）；
- 噪声（EXPECTED_SILENT 上的「待复核」）单独计数并列为观察项——不并入硬错，
  但目标同样为 0（本次靶场实测 0）。

## 理由

- 符合"不把合理的不确定性判成错"：静态工具报「待复核」是在诚实表达不确定性；
- 同时不放过断言级错误：未经机械证据支持的「已确认」是越权断言，必判 FP；
- 二分口径可复算：`truth_check.py` 输出 FP/漏检/档位错/噪声四类计数，任何第三方可重跑复现。

## 后果

- 84 判点的成绩单（84/84，硬错 0，噪声 0）成为可复核的交付材料（`review/truth_result.json`）；
- 若未来出现"应安静上待复核"，先按噪声观察、评估规则收紧，不直接改口径。

## 替代方案（被否）

- 「待复核」也算 FP：会鼓励装死（把不确定输出压成"未发现"），与覆盖诚实矛盾；
- 只算"是否命中"不分档：无法暴露"档位/证据错误"这类真值点。
