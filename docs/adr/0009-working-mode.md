# ADR-0009 · 工作方式：人工触发、一样本一正本、签署后才生效

- 状态：已采纳
- 决策人：周宗正（起草）、余俊辉（复核）
- 关联：`requirements.md` REQ-05/REQ-06/REQ-18、`总档.md` §2.8、`release.md` §2

## 背景

"工作方式"指的是：这个工具在什么时机、被谁、以什么节奏使用；一次分析的生命周期到哪里结束。

如果不定义，会出现几种典型的坏做法：

- 把分析挂成定时任务或文件监听，样本一进来就自动出结论——听起来高效，但结论从此没有人负责；
- 同一个样本反复跑、反复覆盖同一个报告目录——历史结论被悄悄改写，无法解释"上次为什么那么判"；
- 报告生成即视为完成——"人签署"变成流程装饰；
- 把工具接进 CI 当质量门——自动裁决与"教师复评"的评价链条冲突。

## 决策

**人工触发 + 一样本一正本 + 签署后才生效。**

具体规则：

1. **触发**：只由人执行 `python cli.py analyze <apk>`；不提供守护进程、文件监听、定时任务；
2. **正本**：每次分析生成独立 `RUN-<时间戳>/`，**已生成的 RUN 不改写**；重跑 = 新 RUN，不是覆盖；
3. **实验隔离**：调规则时的试错运行必须走 `--no-evidence`，不得写入正本库；
4. **签署**：报告生成后状态为 `human_signoff: pending`；只有具名人抽验并签字后，结论才生效；
5. **变更**：规则/阈值变更 = 版本 bump + `changes.md` 记录 + 靶场回归；不改历史报告的解释；
6. **不接 CI**：自动化只允许做"可复算的检查"（真值一致性、e2e），不允许做"结论裁决"。

## 理由

- 证据纪律第 5 条要求"旧证据不判新版本"，覆盖式重跑会让这条失效；
- 课程明确"人签署、人负责——模型不替代判断"；自动流水线会把责任稀释到"脚本就是这么写的"；
- 一样本一 RUN 的代价是磁盘占用，收益是任何一条历史结论都能回到当时的版本与证据；
- 实验与正本分离，是为了让"试错"可以放开做，而不污染交付材料。

## 后果

- 正面：每条结论都能回答"哪次运行、哪个版本、谁签的"；对抗组可以按 RUN 抽查；
- 负面：吞吐低，不适合几百个样本的批量场景；人工签署是瓶颈；
- 约束：任何"自动化"需求先问一句——它是在替代判断，还是在替代重复劳动？前者不做，后者可以做（如 truth_check）。

## 支撑证据

| 证据 | 位置 | 说明 |
|------|------|------|
| RUN 目录只增不改 | `evidence/RUN-*/` | 6 个批次各自独立，无覆盖 |
| 实验隔离开关 | `release.md` §2（`--no-evidence`） | 试错运行不落正本 |
| 签署台账 | `docs/signoff.md` | 报告需具名人签署 |
| 变更记录 | `docs/changes.md` | 规则变更逐条留痕 |
| 回归脚本 | `scripts/truth_check.py` | 自动化只做可复算检查 |

## 替代方案（被否）

| 方案 | 否决理由 |
|------|----------|
| 监听目录自动分析 | 结论无人触发、无人负责；与签署制冲突 |
| 固定输出目录覆盖写 | 历史结论不可追溯，违反证据纪律第 5 条 |
| 接入 CI 作为质量门 | 自动裁决替代人工判断，与课程评价链条冲突 |
| 生成报告即完成 | "人签署"形同虚设，O1 人机责任无法举证 |
