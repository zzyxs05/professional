# experiment-protocol · 对照实验协议（变量控制与计时口径）

> 项目：APK 通用静态审计（apkaudit）｜交付类：design / eval｜版本：v1.0
> 用途：固化工程对照实验的**自变量、因变量、控制变量与计时规则**。后续新增对照实验沿用本口径，不每次重定。
> 依据：`docs/adr/0002-toolchain-layered-sources.md`、`docs/adr/0004-pin-evidence.md`、`总档.md` §2.2 O4 / §2.8 证据纪律。
> 口径来源：EXP-6 的指标与固定条件写在采集脚本 `scripts/exp_datasource_ab.py` 的 `metrics` / `fixed_conditions` 字段中，随每次运行一起落盘；本文件是同一口径的说明版，不倒填事前审批记录。

---

## 1. 实验要回答什么

围绕一个**已选定的技术决策**，在控制无关变量的前提下，对比两种实现方法的实际效果。变量一次只动一个，避免"改了一堆东西、结果无法归因"。

首轮（EXP-6）选定的决策是 **ADR-0002 四层数据源分层与独立降级**：同一检测目标 `R-CODE-01`（动态代码加载）存在两条独立实现路径，正好构成对照组。

## 2. 变量定义

| 类型 | EXP-6 的取值 |
|------|--------------|
| 自变量（唯一） | 数据源实现：**A** `smali_src` 强模式（apktool 反汇编 + 调用上下文，档位上限「已确认」）／ **B** `dex_strings` 弱模式（自研 dex 类型引用，零外部依赖，档位上限「待复核」） |
| 因变量 | §4 的五项指标 |
| 控制变量 | §3 的全部固定条件 |
| 不允许同时变动 | 规则集、样本集、规则包版本、提示词、模型、报告渲染、证据落盘 |

## 3. 固定条件（不变量）

| 项 | 固定值 |
|----|--------|
| 输入数据集 | `lab/apks/` 6 个自建样本，指纹登记在 `lab/sha256.txt`，逐样本在结果 JSON 中回写 `apk_sha256` |
| 前置数据处理 | apktool 解码产物复用 `%TEMP%/apkaudit_decode/<sha前16位>`；缓存缺失时先补齐解码再开跑，并在结果中记录 `decode_cache_available`。**解码是一次性前置成本，不计入计时** |
| 规则与版本 | 规则包 `0.1.3`；只执行 `R-CODE-01` 一条规则，避免其余 13 条引入变量 |
| 运行环境 | 同一台机器、同一 Python 进程、`time.perf_counter`；不启用通道 B、不调用模型、不联网 |
| 产物边界 | 实验不产生 RUN、不写 `evidence/`；统计 JSON 只写 `review/` |

## 4. 对比指标（运行前定义，随结果落盘）

1. **命中数与命中明细**：每样本命中条数、坐标、`max_status` 档位上限；
2. **样本级检出一致性**：两方法是否都发现目标。**不做坐标级比对**——强模式给 smali 行号，弱模式给 `dex#type` 索引，格式本就不同；
3. **耗时**：解析 + 规则执行的中位数 / 最小 / 最大（ms），以及轮次间命中稳定性；
4. **外部依赖**：A 需 Java + apktool，B 仅标准库；
5. **弱模式匹配口径诊断**：对每个加载器模式分别记录「精确集合成员」与「子串可见」，用于把漏检正确归因到样本还是匹配口径。诊断只读，不改变规则行为。

> 指标口径写死在脚本里，不因结果难看而事后增删；需要新增指标时按 §9 走变更。

## 5. 计时规则

| 项 | 定义 |
|----|------|
| 起点 | 调用 `build_context()` 之前 |
| 终点 | `r_code_01.run(ctx)` 返回之后 |
| 包含 | APK 打开、manifest 直读、dex 扫描、A 组的 smali 索引构建、规则执行 |
| **不包含** | apktool 解码（前置一次性）、报告渲染、证据落盘、模型调用 |
| 计时工具 | `time.perf_counter()`，单位毫秒，保留 3 位小数 |
| 重复 | 每方法先预热 1 次（不计时），再正式计时 N 次（默认 5） |
| 异常轮次 | 记 `error` 并从耗时统计剔除，不静默丢弃；全失败时明确写「无有效数据」 |

**边界说明**：A 组耗时含 smali 索引构建，B 组不含——这是两种实现方法的固有差异，属于被测对象本身，不是干扰变量。由于解码被排除，本实验**不**给出端到端工具链成本比较，只给"解析 + 规则执行"阶段的可比耗时。

## 6. 真实运行与观测依据

- 结果文件 `review/exp_datasource_ab.json` 含 `generated_at`、Python/平台版本、规则包、逐样本 sha256、逐轮耗时与命中明细；
- 所有统计由脚本对真实运行结果计算，**模型不参与统计、不生成结论**；`docs/experiments.md` 的结论只引用已落盘数据；
- 失败与负结果原样保留，不因假设被否定而删轮次、改口径或补写"预期更优"的表述；
- 评价口径沿用项目纪律：哈希证明完整性，不证明真实性；静态证据层级上限 STATIC。

## 7. 有效性边界

- 只比一条规则的双源实现，结论不外推到全部 14 条规则；
- 样本为自建合成（1 个正例 + 5 个安静点），不外推到真实第三方应用；
- 弱模式诊断只记录匹配口径事实，**不修改规则、阈值或规则包版本**；任何修复走 Change 流程（bump 版本 + `docs/changes.md` + 重跑 84 判点）；
- 计时不含解码，因此"零依赖更快"只适用于解析阶段，不代表完整链路成本。

## 8. 复算

```bash
python scripts/exp_datasource_ab.py --runs 5                 # 全 6 样本
python scripts/exp_datasource_ab.py --runs 5 --samples bad03 # 单样本复核
```

复算会覆盖 `review/exp_datasource_ab.json`；如需保留历史结果，先另存并用 `--out` 指定路径。

## 9. 协议变更

改指标、不变量或计时口径 = 升本协议版本 + 记 `docs/changes.md` + 重跑实验；**历史结果 JSON 不改写**，新旧口径并列保留，比较时注明版本差异。
