## 1. 问题：不是"扫不出问题"，是"结论没法被复核"

APK 静态审计这个领域不缺工具。MobSF 能做静态+动态一体分析并映射 MASVS，apkleaks 能从 APK 里把密钥和端点捞出来，APKiD 能识别加固与混淆，Androguard 能当库被任意流水线调用（调研见 `research/apk-audit-landscape.md`）。

真正缺的是另一件事：**当一份报告说"这个应用有问题"时，第三方能不能不重跑工具、只按报告里的坐标就把这句话验证掉。**

现状是：

- 报告给结论，不给"这条结论的原文在哪一行"——复核方只能选择相信或不信；
- 工具把"有结构"和"有行为"混在一起说——"存在定时器 + 存在录音 API"被写成"半夜自动录音"；
- 没跑的部分不声明——"未发现"被读成"安全"；
- 把模型生成的长文当分析报告——文字通顺，但每个数字、每条引用都可能是编的。

本项目要解决的就是这一段：**输入任意（非加固）APK，产出「每条结论都带证据、可被第三方独立复核」的静态审计报告。**

## 2. 谁在用、在什么场景用

| 角色 | 场景 | 他要的东西 |
|------|------|-----------|
| 复核者（对抗组 / 教师 / 组内验证者） | 拿到报告，抽查 2—3 条关键结论 | 坐标能直达原文；证据文件真存在；没查的部分有声明 |
| 分析者（本组实现者 / 安全初学者） | 改一条规则，看会不会破坏基线 | 误报口径写清楚了；84 判点能重跑；历史报告不被改写 |
| 降级场景下的使用者 | 机器上只有 Python，没有 Java | M/S 类照样出结论；P/C/N 类明确列为未覆盖，不静默 |

完整角色定义与"不服务谁"见 `requirements.md` §1。

## 3. 为什么现在做（调研结论）

1. 检测能力已被成熟工具覆盖，重复造一个扫描器没有增量价值；
2. "证据可复核"这一层，现有工具都只做到报告级，没有强制到"每条结论 + 坐标 + 哈希"；
3. LLM 介入静态审计的正确位置尚未形成惯例，两类错误用法（直接下结论 / 自由写报告）正在被大量使用；
4. OWASP 把 Overreliance 列为独立风险项，说明"模型输出必须被批判性复核"已经是共识，而不是本项目的保守选择。

这四点推导出 6 条稳定需求（UN-01—UN-06），见 `requirements.md` §3。

## 4. 范围

**做（in scope）**

- 14 条 P0/P1 静态规则的确定性检测（M/P/S/C/N 五类，见 `specification.md` §2）；
- 双通道语义审查：A 通道确定性规则 + B 通道 LLM（B1 复核、B2 敏感区扫描）；
- 融合层与钉证据机制；三档结论（已确认 / 待复核 / 无法判定）；
- 报告双渲染（`report.md` 人读 / `report.json` 机器读）+ 覆盖声明；
- 真值一致性自评（`lab/` 靶场 6 样本 × 14 规则 = 84 判点）；
- 评价器（独立角色，四状态输出，受限工具）。

**不做（out of scope）**

- 加固样本（不脱壳）、动态分析（不执行被测 APK）、真实第三方应用结论发布；
- MASVS 全量覆盖（只做静态可判、能出机械证据的部分，覆盖对照见调研 §4）；
- 拖库式的"规则数量竞赛"——规则集只收有证据模板、有真值的条目；
- GUI / Web 服务（交付形态见 ADR-0007）。

## 5. 成功标准

| 维度 | 标准 | 怎么验 |
|------|------|--------|
| 可复核 | 任意抽 5 条结论，按坐标直达原文成功 | 人工抽验（`signoff.md`） |
| 诚实 | 三档状态不越规则上限；"未发现"必带覆盖声明 | 脚本 + 人工 |
| 一致 | 靶场 84 判点与真值一致，硬错 0 | `scripts/truth_check.py` |
| 可复现 | 同输入 + 同版本 → 同报告（A 通道逐字段） | `scripts/e2e.py` |
| 可降级 | 缺模型 / 缺 apktool 时不崩溃、不静默 | A-07 用例 |
| 可交接 | 他人在干净环境按 handoff 跑通 | 对抗组复核 |

> 成功标准里**没有**"规则条数""报告长度""Finding 数量"——这三项按课程要求不自动加分。

## 6. 验收 ID

| ID | 一句话 | 判定 |
|----|--------|------|
| A-01 | 全输入受理：不挑样本、不崩溃、失败如实报告 | 脚本 + 人工 |
| A-02 | 靶场真值一致性 84/84（判罚分解口径见矩阵） | `scripts/truth_check.py` |
| A-03 | 三档结论 + 覆盖声明（"未发现"必须带覆盖声明） | 脚本 + 人工 |
| A-04 | 每条结论带可定位坐标（smali 行号+原始行 / manifest 区间 / dex#str） | 脚本 + 人工 |
| A-05 | 证据落盘且报告引用可回溯（evidence_id 存在性预检） | 评价器预检 |
| A-06 | 报告绑定规则包版本与模型版本 | 脚本 |
| A-07 | 通道 B 缺失/失败自动降级并声明（可降级是硬要求） | 脚本 + 人工 |
| A-08 | 评价器只输出四状态（PASS/FAIL/INSUFFICIENT_EVIDENCE/NOT_APPLICABLE） | 评价器自检 |
| A-09 | 确定性复现：同输入 + 同版本 + 干净环境 → 同一份报告 | 人工 + 脚本 |
| A-10 | 合规：只读不执行、子进程白名单、数据边界 | 代码审查 |
