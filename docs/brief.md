# brief · 问题、范围、验收 ID、责任

> 交付类：brief　｜　上游：总档.md §1/§2　｜　版本：v0.1（2026-10-14）

## 1. 问题

App 安全审计里，"说了什么问题"经常无法被第三方复核：结论没有坐标、证据没有落盘、
静态误报与漏报混在一起、失败被写成通过。本项目要解决的问题是：

**输入任意（非加固）APK，产出「每条结论都带证据、可被第三方独立复核」的静态审计报告。**

## 2. 范围

**做（in scope）**

- 14 条 P0/P1 静态规则的确定性检测（M/P/S/C/N 五类，见 `specification.md` §2）；
- 双通道语义审查：A 通道确定性规则 + B 通道 LLM（B1 复核、B2 敏感区扫描）；
- 融合层与钉证据机制；三档结论（已确认 / 待复核 / 无法判定）；
- 报告双渲染（`report.md` 人读 / `report.json` 机器读）+ 覆盖声明；
- 真值一致性自评（`lab/` 靶场 6 样本 × 14 规则 = 84 判点）；
- 评价器（独立角色，四状态输出，受限工具）。

**不做（out of scope）**

- 加固样本（不脱壳）、动态分析（不执行被测 APK）、真实第三方应用结论发布；
- 拖库式的"规则数量竞赛"——规则集只收有证据模板、有真值的条目。

## 3. 验收 ID（详表见 `acceptance-matrix.md`）

| ID | 一句话 | 判定 |
|----|--------|------|
| A-01 | 全输入受理：不挑样本、不崩溃、失败如实报告 | 脚本 + 人工 |
| A-02 | 靶场真值一致性 84/84（判罚分解口径见矩阵） | `scripts/truth_check.py` |
| A-03 | 三档结论 + 覆盖声明（"未发现"必须带覆盖声明） | 脚本 + 人工 |
| A-04 | 每条结论带可定位坐标（smali行号+原始行 / manifest区间 / dex#str） | 脚本 + 人工 |
| A-05 | 证据落盘且报告引用可回溯（evidence_id 存在性预检） | 评价器预检 |
| A-06 | 报告绑定规则包版本与模型版本 | 脚本 |
| A-07 | 通道 B 缺失/失败自动降级并声明（可降级是硬要求） | 脚本 + 人工 |
| A-08 | 评价器只输出四状态（PASS/FAIL/INSUFFICIENT_EVIDENCE/NOT_APPLICABLE） | 评价器自检 |
| A-09 | 确定性复现：同输入+同版本+干净环境 → 同一份报告 | 人工 + 脚本 |
| A-10 | 合规：只读不执行、子进程白名单、数据边界 | 代码审查 |
