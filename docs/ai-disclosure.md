## 3. 被拒绝 / 修正的 AI 建议（示例记录，持续追加）

| 日期 | AI 建议 | 处置 | 原因 |
|------|---------|------|------|
| 2026-10-14 | R-MAN-04 对"未声明 allowBackup"不报（只报显式 true） | **部分采纳+标注** | 默认值 true 属实，但必须标注"未显式声明"避免措辞升级 |
| 2026-10-14 | R-CODE-02 解析布尔实参（setJavaScriptEnabled(true/false)） | 暂缓 | P0 复杂度不值得；记为 changes.md 观察项，出现误报再升级 |
| 2026-10-14 | 用 LLM 直接给 B2 疑点定档 | 拒绝 | 违反 ADR-0004（钉证据机制）：LLM 无权升级结论 |
| 2026-10-15 | 用否定式禁令（"不要/不许/禁止/宁缺毋滥"）约束 B 通道输出 | **项目负责人指出后整改** | 这些禁令是"改提示词→跑→看输出→再改"多轮调教的沉淀，在**输出端**裁掉了模型的独立判断；总档只授权"结论天花板=待复核 + 升级靠钉证据"，未授权限制 B 的审查范围。整改：删除全部否定指令 → 改为数据结构约束（输出 schema 字段、`confidence` 枚举分流、程序统计供数）+ 报告 `observations` 观察区承载模型原声。**实证：去禁令后 B1 仍按口径判"确认可疑"，并用 observation 说出"疑似示例值"——禁令本不必要** |
| 2026-10-14 | 钉证据初版（AI 实现）"claim 实体存在即钉成功" | **实跑暴露后修正** | 产生假证据式「已确认」（bad02 R-B-001）：claim 提 INTERNET、证据只证了 INTERNET 权限存在——断言未被验证。修正为规则映射+机械复核+实体级核对（changes.md B5）。教训：**AI 的实现缺陷由真实运行暴露、由契约纪律修正**，流程有效 |
