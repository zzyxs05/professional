# APK 通用静态审计（apkaudit）

> 性质：brief ｜ 版本：v1.0 ｜ 状态：生效
> 职责：给人指路——项目是什么、怎么跑、文档去哪找；不展开规则、接口和进度的完整内容。
> 关联：上游 `总档.md`；下游 `GLOBAL.md`、`PLAN.md`、`TASKS.md`、`HARNESS.md`、`handoff/README.md`。
> 签署：状态统一见 `docs/signoff.md`，本文不设独立签署栏。

给一个没有加固的 APK，找出权限、组件、硬编码凭据、动态加载、传输安全这几类问题，每条结论都带代码位置和证据，别人照着位置就能自己核对。

两个人做：周宗正（主要实现）、余俊辉（验证与评价器）。结对组是毛舒逸组。

## 现在能跑出什么

- 14 条规则，6 个自建样本，结论和真值表对得上 **84/84**，硬错 0；
- 报告分三档：已确认 / 待复核 / 无法判定，另附覆盖声明；
- 一个评价 Agent：自己决定读哪份证据、调哪个工具，给出四状态与逐项评测分（非课程最终成绩），不替人下结论；
- 零第三方依赖（Python 3.8+ 标准库）；apktool 随仓库带着，克隆下来就能跑。

## 三条命令

```bash
python cli.py analyze lab/apks/bad03.apk # 审计一个样本，产物写进 evidence/RUN-<时间>/
python -m unittest discover -s tests # 94 个单元测试
python scripts/truth_check.py --no-run # 复算 84 个判点，不重跑样本
```

完整命令和参数见 `总档.md` 第 6 节，交接说明见 `handoff/README.md`。

每份文档只回答一个问题，同一件事不写第二遍。下表是唯一入口；找不到的东西，说明它还没写。

## 三类东西不要混

- `evidence/`：程序跑出来的事实，只增不改；
- `review/`：人对这些事实的解释、复核和签署；
- `docs/`：事先约定的规则和事后的记录。

报告里的每条结论都要能指回 `evidence/` 里的具体文件和行号；指不回去的，不允许写成"已确认"。

## 边界

只做静态分析，样本只读不执行；不含加固应用；不对真实上架应用下结论。证据强度上限就是 STATIC，报告里不会出现"动态验证过"这种说法。
